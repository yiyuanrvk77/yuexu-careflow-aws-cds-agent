# 约序 CareFlow：基于 AWS CDS 的智能预约运营 Agent

## 业务问题

预约制服务机构每天都在处理改约、取消、空档填补和客户提醒。客户可能通过短信、RCS、WhatsApp 或邮件联系，但前台需要在不同系统和聊天工具之间切换，反复确认客户身份、查询可用时间并手动更新预约。

一次爽约不仅损失预约收入，还会浪费已经预留的服务人员和场地。客户临时取消后，人工也很难及时找到候补客户填补空档。

## 解决方案

约序是一个能够完成预约业务动作的 Agentic AI 应用，而不是只回答常见问题的聊天机器人。

客户通过 AWS CDS 发送消息后，系统会：

1. 将入站事件标准化并识别渠道；
2. 从手机号或邮箱解析统一客户 ID；
3. 调用 Amazon Bedrock AgentCore Runtime；
4. 由 Strands Agent 使用 Bedrock 模型理解客户目标；
5. 调用预约查询、时段搜索、锁定、改约、取消和候补工具；
6. 在客户明确确认后执行 DynamoDB 事务；
7. 通过 AWS CDS 将结果发送给客户。

## Agentic 能力

Agent 不是按固定关键词直接发送模板，而是根据客户表达选择工具和工作流程。例如：

- 先查询客户现有预约，再搜索指定日期和时段；
- 向客户提供最多三个准确可约时间；
- 客户选择后临时锁定五分钟；
- 只有客户在当前消息中明确确认，才执行改约；
- 如果时段已被占用，向客户解释冲突并重新查询；
- 将旧时段写入候补机会。

确认检查同时存在于系统提示词和工具代码中。DynamoDB 条件写入和事务会进一步验证预约版本、时段状态和客户归属。

## AWS 架构

- **AWS End User Messaging SMS/RCS**：双向短信与 RCS 消息；
- **AWS End User Messaging Social**：WhatsApp 消息；
- **Amazon SES**：预约确认邮件；
- **Amazon SNS + SQS**：渠道事件缓冲和重试；
- **AWS Lambda**：事件标准化、AgentCore 调用和 CDS 发送；
- **Amazon Bedrock AgentCore Runtime**：托管 Agent 运行环境；
- **AgentCore Memory**：客户偏好和历史上下文；
- **Amazon Bedrock**：模型推理和工具选择；
- **Amazon DynamoDB**：预约、时段锁定、会话、幂等和候补状态；
- **Lambda Function URL**：受 Token 和白名单保护的评委测试入口；
- **AWS CDK + AgentCore CLI**：可重复部署。

## 业务价值

第一阶段目标客户是连锁口腔、体检中心、康复机构和宠物医院。可衡量的价值指标包括：

- 单次改约所需前台工时；
- 预约爽约率；
- 临时取消时段被候补客户填补的比例；
- 从客户发消息到改约完成的时间；
- 非营业时间完成的预约操作比例；
- 客户满意度。

同一套预约运营能力可以复用于汽车售后、美容、教育、家政和兽医等预约制行业。

## 安全与责任边界

约序只处理预约行政事务，不进行诊断、不解读检查结果，也不提供用药建议。涉及临床、紧急或其他高风险请求时，会提示客户等待门店人员跟进，不会声称已经完成人工转接。

系统不会把 DynamoDB 主键或内部客户 ID 暴露给客户，也不会把原始手机号或邮箱放进模型提示词。

## 当前 MVP 边界

- 单租户、单门店；
- 当前演示服务为 `dental-cleaning`；
- 短信、RCS、WhatsApp 支持入站和出站；
- 邮件当前只支持出站；
- 候补机会可以创建，但自动候补邀约尚未实现；
- 人工接管和 EventBridge 自动提醒属于下一阶段。
